# SPEC — split-drag-ux：VSCode 式 tab 分栏拖拽体验优化

> 迭代规格（R27）。基线：`.agents/specs/pi-web/SPEC.md` §7（前端交互）/ §10（模块划分与测试策略）。结构现状以代码为准（基线 §7 中 `web/` 描述已过时，前端现为 `src/client` FSD：app/pages/features/entities/shared）。

## Problem Statement

pi-web 控制台的 tab 分栏（split）拖拽交互与用户的 VSCode 使用经验不符，存在 5 个问题：

1. **split 后聊天 tab 鬼畜**：滚动条一闪一闪（先消失又加回），直到用户第一次手动滚动才恢复正常。
2. **单 tab 拖拽也触发 split 预览**：一个组只有 1 个 tab 时拖动也显示预览，但 drop 后视觉无任何变化（预览欺骗）。
3. **预览与实际分栏不一致**：拖拽预览高亮显示 1/4 区域，实际 split 后是 1/2 对半分。
4. **已 split 后跨分栏拖拽无效**：从一分栏拖 tab 到另一分栏的正文区域，预览显示了但放手什么都不会发生；只有拖到对方 tab 栏才有效。
5. **跨 split 的 tab 移动落点过窄**：必须拖到对方组的某个 tab 正上方才能移动；且插入位置恒为"被悬停 tab 之前"（只能放左边），无法放到 tab 之后或末尾空白处。

## Solution

以 VSCode 的 tab/编辑器组拖拽模型为基准，重构分栏拖拽的落点语义与预览：

- **停靠区模型**：目标分栏的正文区域 = 左缘（在左侧拆分）+ 中央（并入该组，join）+ 右缘（在右侧拆分），上下同理；目标组的整条 tab 栏（含空白区）都可作为移动落点。
- **预览 = 实际结果**：边缘预览高亮实际拆分后的半区（50%）；join 预览高亮整个目标组（淡高亮）；命中区判定保持 25% 贴边（仅判定用，不再等于高亮区域）。
- **单 tab 守卫**：源组只有 1 个 tab 且目标 = 源组时，不显示任何预览、drop 无效果（拆分无意义）；拖到其他组/边缘仍有效。
- **跨组拆分**：拖 tab 到其他组边缘 = 从源组移除、目标组一分为二、tab 放入新组（源组空自动回收）。
- **tab 栏整条可落**：目标组 tab 栏（含 tab 间隙与末尾空白）均可 drop；插入位置按落点 x 坐标决定（tab 左半 → 插其前，右半 → 插其后，末尾空白 → 追加末尾），并显示 VSCode 式插入竖线指示器；同组重排与跨组移动共用同一模型。
- **滚动稳定性**：移除 autoscroll 期间的滚动条隐藏（根治闪烁）；split 重挂载后恢复各分栏的滚动位置（不跳底）。

## User Stories

1. 作为 web 控制台用户，我希望 split 后聊天区不再闪烁、滚动条稳定显示，以便我能连续阅读消息流而不被视觉干扰打断。
2. 作为 web 控制台用户，我希望一个组只有一个 tab 时拖动它不出现任何 split 预览，以便不被无意义的预览误导。
3. 作为 web 控制台用户，我希望拖拽预览高亮的区域与实际 split 结果一致（边缘 = 半区），以便所见即所得。
4. 作为 web 控制台用户，我希望把 tab 拖到另一个分栏的正文中央时 tab 并入该组（与已有 tab 并列、激活），以便把会话合并到另一栏。
5. 作为 web 控制台用户，我希望把 tab 拖到另一个分栏的左缘/右缘时在该侧拆出新分栏放置该 tab（跨组拆分，源组空自动回收），以便把一个会话拆到另一栏。
6. 作为 web 控制台用户，我希望拖 tab 到目标组的 tab 栏任意位置（含空白区）都能移动，并按落点 x 位置插入（tab 前/后/末尾），以便精确控制 tab 顺序。
7. 作为 web 控制台用户，我希望跨组移动/重排时看到插入竖线指示器，以便放手前知道 tab 将落在哪里。
8. 作为 web 控制台用户，我希望 split 后各分栏保留自己原来的滚动位置（不因重挂载跳到底部），以便 split 前后阅读上下文不中断。
9. 作为 web 控制台用户，我希望单 tab 组的 tab 拖到其他组仍有效（移动/并入），以便只有一个 tab 时也能整理布局。

## Implementation Decisions

- **领域层（布局树纯函数）扩展，签名兼容**：
  - 落点判定函数返回类型扩展为 `SplitSide | "join"`：边缘（x<0.25 / x>0.75 / y<0.25 / y>0.75）返回对应方向，中央返回 `"join"`（原返回 `null`）。
  - 拆分函数扩展为支持跨组：被拖 tab 可在任意组（内部定位源组），目标组一分为二、被拖 tab 移入新组、源组移除该 tab（复用关闭语义激活相邻）、空组自动回收。**守卫：源组 = 目标组且源组 tabs=1 → 返回原树**（拆分无意义）。同组拆分的行为与现有一致（现有测试不破坏）。
  - join 复用现有移动函数（`toId = null` = 追加末尾 + 激活目标组），不新增路径。
- **分栏视图层**：
  - 预览守卫：拖拽中 tab 的源组 = 目标组 且 源组仅 1 个 tab → 不显示预览、drop 无效果（用布局树纯函数定位源组）。
  - drop 分发：`join` → join 回调（接线到移动 action，`toId = null`）；四向 side → 拆分回调（现有接线，跨组语义由领域层扩展承载）。
  - 高亮层：边缘 = 实际半区（50%，四向统一）；join = 目标组整容器淡高亮。
- **tab 栏层**：
  - 插入位置解析抽为纯函数：输入各 tab 元素边界列表（left/width）+ 落点 x → 插入序号（0..n，n = 末尾）；判定规则 = 与各 tab 中点比较。
  - tab 栏容器（含 tab 间隙与空白区）成为有效 drop target（dragover preventDefault 不再限于空栏）；tab 元素上 drop 也按 x 判定（左半 before / 右半 after），不再恒为 before。
  - 悬停指示状态扩展为 `{tabId, 位置}`（before/after/末尾），渲染绝对定位竖线指示器。
- **滚动（issue 1）**：
  - 移除 autoscroll 时隐藏滚动条的样式挂钩（视觉根治；滚动条常显 thin）。
  - 滚动位置保留：聊天页卸载时上报"当前可见消息锚点"（取可见消息列表首条 id），重挂载且消息就绪后 `scrollToMessage(锚点)` 恢复；锚点失效（消息已不存在）则保持默认贴底。锚点存于 App 级 ref（与既有状态快照恢复同模式），不影响聊天流 reducer 领域状态。
- **不变量**：布局树结构（split/leaf 二叉树）、localStorage 持久化格式、sash 比例调整（0.2–0.8 + 160px 下限）均不变。

## Testing Decisions

测试只测外部行为（用户可观察的落点/预览/移动结果），不测内部实现。测试 seam（按优先级）：

- **Seam S1（最高，纯函数 seam）**：布局树领域层——落点判定（四向边缘 / 中央 join）、跨组拆分（含单 tab 守卫、空组回收）、join 追加末尾语义。先例：该层已有完整单测（拆分、移动、空组合并、比例 clamp）。
- **Seam S2（组件 seam）**：分栏视图——渲染 + 模拟 drag 事件：预览守卫（单 tab 组内不预览）、中央 dragover → join 高亮、drop → join/拆分回调、高亮区域类（边缘半区 / join 整容器）。先例：该组件已有 drag/drop 渲染测试。
- **Seam S3（组件 + 纯函数 seam）**：tab 栏——插入位置解析纯函数（边界列表 + x → 序号）；组件测试：tab 栏空白区可 drop、tab 上 drop 按 x 传 before/after、指示器渲染。先例：该组件已有拖拽测试。
- **Seam S4（视觉/契约）**：滚动——样式挂钩移除无单测（浏览器冒烟验收）；滚动锚点上报/恢复做 prop 契约级测试（卸载上报、重挂恢复调用），真实滚动行为浏览器冒烟验收（AGENTS.md 验收步：E2E 只做冒烟）。

验收总门：`npm test` + `npm run typecheck` 全绿 + 浏览器冒烟（5 个 issue 逐一验证）。

## Out of Scope

- sash 分割线比例调整（已实现，不碰）、比例持久化（已实现，不碰）。
- 上下（col）split 的模型扩展（已支持，仅统一预览高亮）。
- 最大分栏数限制（现状无上限，保持）。
- 键盘快捷键、tab 右键菜单、关闭组按钮。
- 布局树的序列化格式变更。
- 其他非 split 的拖拽（侧栏宽度、文件树等）。

## Further Notes

- 全部交互行为以 VSCode 为基准（用户指定），grilling 阶段已逐项对齐（Q1–Q9 全部确认）。
- 被拖 tab 的源组定位、预览守卫等均通过既有纯函数（按 tab 找组 / 按组找 leaf）实现，不新增跨层状态。
- 现有测试中"拖到中央：无高亮、drop 不触发"的断言将随本次语义变更而更新（中央 → join）。
